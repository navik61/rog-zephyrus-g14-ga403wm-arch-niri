# GPU on ASUS ROG Zephyrus G14 GA403WM — installation and setup

[Čeština](gpu-nvidia-amd.md) | **English**

Verified 2026-11-25 on: kernel `linux` 7.3.6-arch1-1, `nvidia-open-dkms` 620.73.04,
Mesa 26.3.1, systemd-boot + UKI, niri compositor (uwsm).

## Hardware

| | Device | PCI | Driver |
|---|---|---|---|
| iGPU | AMD Radeon 880M/890M (Strix) | `65:00.0` | `amdgpu` |
| dGPU | NVIDIA GeForce RTX 5060 Laptop (GB206, Blackwell) | `64:00.0` | `nvidia` (open) |

- **Mode:** `Hybrid` (supergfxctl), MUX = Optimus → the internal display (`eDP-1`) is on **AMD**,
  NVIDIA wakes up only on demand (`prime-run`). Backlight is controlled by `amdgpu_bl1`.
- **HDMI and one DP/USB-C output** are wired to NVIDIA (`card0-HDMI-A-1`, `DP-*`) —
  an external monitor on them wakes the dGPU.
- Blackwell supports **open modules only** (`nvidia-open-dkms`), the proprietary `nvidia-dkms` does not work.

## 1. Packages

```bash
# AMD (iGPU)
sudo pacman -S mesa lib32-mesa vulkan-radeon lib32-vulkan-radeon

# NVIDIA (dGPU)
sudo pacman -S linux-headers nvidia-open-dkms nvidia-utils lib32-nvidia-utils \
               nvidia-settings nvidia-prime opencl-nvidia libva-nvidia-driver

# Common / tools
sudo pacman -S vulkan-icd-loader lib32-vulkan-icd-loader vulkan-tools libva-utils nvtop

# ASUS (g14 repo or AUR)
asusctl supergfxctl
```

**Do not install:**
- `nvidia-bl-dkms` — a backlight driver for old MacBooks. Useless on the G14 and it fails to
  build with kernel 7.3 (DKMS error on every kernel update).
- `nvidia-dkms` (proprietary) — does not support Blackwell.
- `xf86-video-nouveau` — `nouveau` is blacklisted (see below).

## 2. Kernel parameters (UKI)

File `/etc/kernel/cmdline`:

```
root=PARTUUID=… rw rootfstype=ext4 zswap.enabled=0 amd_pstate=active amdgpu.ppfeaturemask=0xffffffff nvme_core.default_ps_max_latency_us=0
```

| Parameter | Why |
|---|---|
| `amd_pstate=active` | EPP CPU frequency control (saves battery) |
| `amdgpu.ppfeaturemask=0xffffffff` | *Optional.* Unlocks iGPU overdrive/undervolt. Drop it if you don't tune the iGPU — otherwise the kernel reports "Overdrive is enabled" |
| `nvidia_drm.modeset=1` | *Redundant.* Default since driver 560; it is also in modprobe. Harmless |

Rebuild the UKI after changing the cmdline:

```bash
sudo mkinitcpio -P
```

## 3. Modules (`/etc/modprobe.d/`)

### `nvidia.conf` — recommended content

```
options nvidia NVreg_EnableS0ixPowerManagement=1 NVreg_DynamicPowerManagement=0x02
```

- `NVreg_DynamicPowerManagement=0x02` — fine-grained dGPU power-down (RTD3) when unused.
- `NVreg_EnableS0ixPowerManagement=1` — proper suspend to S0ix (modern standby).
- **Do not use `NVreg_EnableGpuFirmware=0`** — the open driver on Blackwell always requires the
  GSP firmware, the parameter has no effect (it only confuses). Removed 2026-11-20; verify after
  reboot: `sudo grep EnableGpuFirmware /proc/driver/nvidia/params` (should be the default, not `0`).
- `options nvidia_drm modeset=1` — redundant, can be omitted.

### `supergfxd.conf` (generated by supergfxd, do not edit)

```
blacklist nouveau
alias nouveau off
options nvidia-drm modeset=1
```

## 4. Initramfs (`/etc/mkinitcpio.conf`)

```
MODULES=()
HOOKS=(base udev autodetect microcode modconf kms keyboard keymap consolefont block filesystems fsck)
```

`/etc/mkinitcpio.conf.d/asus.conf`:

```
MODULES+=(hid_asus asus_wmi asus_nb_wmi)
```

- NVIDIA modules **don't need to be added** to the initramfs — the display is on AMD, early KMS
  for NVIDIA brings nothing (just a bigger UKI and the need to rebuild it on every driver update).
- The warning `Possibly missing firmware for module: 'nouveau'` is harmless.

### When to rebuild the UKI (`sudo mkinitcpio -P`)

Boot is systemd-boot + UKI: `/etc/mkinitcpio.d/linux.preset` has `default_uki=` and
`mkinitcpio -P` does not create a separate initramfs but the whole
`/boot/EFI/Linux/arch-linux.efi` (kernel + initramfs + cmdline + splash in one file). The output
should contain `Creating unified kernel image: '/boot/EFI/Linux/arch-linux.efi'`.

| Change | Rebuild? |
|---|---|
| `/etc/kernel/cmdline` | **Always** — the cmdline is baked into the UKI |
| `/etc/mkinitcpio.conf`, `/etc/mkinitcpio.conf.d/*` | **Always** |
| `/etc/modprobe.d/*` | Only if the module is loaded from the initramfs. The `modconf` hook copies the files into the UKI, but NVIDIA modules are not in it — they load from disk and read the current `/etc/modprobe.d/`. For consistency, feel free to always rebuild |
| Kernel / driver update | Done automatically by a pacman hook |

Changes take effect after a reboot. UKI contents can be checked with:

```bash
sudo lsinitcpio /boot/EFI/Linux/arch-linux.efi | grep -E 'nvidia|modprobe.d'
```

## 5. Services

```bash
sudo systemctl enable nvidia-suspend.service nvidia-hibernate.service nvidia-resume.service
sudo systemctl enable --now nvidia-powerd.service   # Dynamic Boost
sudo systemctl enable --now supergfxd.service
sudo systemctl enable nvidia-rtd3-rebind.service    # see section 6
```

**Do not enable** `nvidia-persistenced` — it would keep the dGPU awake all the time.

GPU mode:

```bash

supergfxctl -m Hybrid   # iGPU + dGPU on demand (recommended)
```

## 6. RTD3 workaround for kernel 7.3+ (temporary)

### Problem

On kernel 7.3+ the driver reports `Runtime D3 status: Not supported` and the dGPU **never
suspends** (~4 W extra, permanently). Cause: since 7.3 kernel threads run in an empty root
(nullfs), the `nv-probe` probe thread cannot open `/sys/bus/pci/devices/…/config` and the driver
silently disables RTD3.
Upstream: [NVIDIA/open-gpu-kernel-modules#1507](https://github.com/NVIDIA/open-gpu-kernel-modules/issues/1507)
(fix = PR #1512, not merged as of 2026-11-20; 620.73.04 is affected).

Solution: after boot, **before anyone opens the card**, unbind it and bind it to the driver again
from a regular process.

### `/usr/local/sbin/nvidia-rtd3-rebind` (`chmod 755`)

The script is in this repo: [`system/usr/local/sbin/nvidia-rtd3-rebind`](../system/usr/local/sbin/nvidia-rtd3-rebind)
What it does, for each NVIDIA GPU reporting `Runtime D3 status: Not supported`:

1. skips the card if anyone holds `/dev/nvidia*` or its DRM nodes (`fuser`) — otherwise
   unbind would hang;
2. removes `nvidia_drm`, `nvidia_modeset`, `nvidia_uvm` with `rmmod` (not `modprobe -r`,
   which would also remove `nvidia` itself and `/sys/bus/pci/drivers/nvidia` would disappear);
3. writes the PCI address to `/sys/bus/pci/drivers/nvidia/unbind` and `…/bind`;
4. loads `nvidia_drm` and `nvidia_uvm` again and logs the new RTD3 status.

### `/etc/systemd/system/nvidia-rtd3-rebind.service`

```ini
[Unit]
Description=Rebind NVIDIA GPU to enable RTD3 (workaround open-gpu-kernel-modules#1507)
After=systemd-modules-load.service systemd-udevd.service
Before=nvidia-powerd.service nvidia-persistenced.service supergfxd.service display-manager.service systemd-user-sessions.service
ConditionPathExists=/sys/bus/pci/drivers/nvidia

[Service]
Type=oneshot
ExecStartPre=/usr/bin/udevadm settle --timeout=30
ExecStart=/usr/local/sbin/nvidia-rtd3-rebind
TimeoutStartSec=60

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable nvidia-rtd3-rebind.service
```

### ⚠️ Lessons learned (what not to do)

- **Never unbind while someone holds the card** (browser, `nvidia-powerd`, …).
  The write to `unbind` then gets stuck in the kernel, the process can't be killed and **the
  system can't shut down** (only holding the power button ~10 s helps). The script guards this
  with `fuser`.
- **Don't use `modprobe -r nvidia_drm nvidia_modeset nvidia_uvm`** — it also removes the
  `nvidia` module and the rebind has nothing to bind to.
- Manual test at runtime: `sudo systemctl stop nvidia-powerd`, verify that `sudo lsof /dev/nvidia*`
  is empty, then `sudo /usr/local/sbin/nvidia-rtd3-rebind` and `sudo systemctl start nvidia-powerd`.

### Removal (once a fixed driver is released)

```bash
sudo systemctl disable nvidia-rtd3-rebind
sudo rm /etc/systemd/system/nvidia-rtd3-rebind.service /usr/local/sbin/nvidia-rtd3-rebind
sudo systemctl daemon-reload
```

Keeping it does no harm — the script does nothing unless the card reports "Not supported".

## 7. Apps on the iGPU only (so they don't wake the dGPU)

GTK4 (Vulkan renderer), Firefox/Zen etc. open **all** drivers including NVIDIA through the
glvnd/Vulkan loader → `/dev/nvidia*` stays open and the dGPU never suspends, even though nothing
is rendered on it. For a specific application this fixes it:

```bash
export __EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/50_mesa.json
export VK_DRIVER_FILES=/usr/share/vulkan/icd.d/radeon_icd.json
export LIBVA_DRIVER_NAME=radeonsi
```

**Do not set these globally** (environment.d, uwsm env) — it would break `prime-run` for games/CUDA.

### Zen Browser — `~/.local/bin/zen-browser` (takes precedence over `/usr/bin` in PATH)

```sh
#!/bin/sh
export __EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/50_mesa.json
export VK_DRIVER_FILES=/usr/share/vulkan/icd.d/radeon_icd.json
export LIBVA_DRIVER_NAME=radeonsi
exec /opt/zen-browser-bin/zen-bin "$@"
```

For launchers and opening links, override the `.desktop` file:

```bash
sed 's#^Exec=/opt/zen-browser-bin/zen-bin#Exec=$HOME/.local/bin/zen-browser#' \
    /usr/share/applications/zen.desktop > ~/.local/share/applications/zen.desktop
update-desktop-database ~/.local/share/applications
```

(Replace `$HOME` with your actual home path — `.desktop` files don't expand variables.)
Repeat the command after a Zen update that changes the system `zen.desktop`.

### Python GTK apps

Directly in the script, **before `import gi`**:

```python
os.environ.setdefault("VK_DRIVER_FILES", "/usr/share/vulkan/icd.d/radeon_icd.json")
os.environ.setdefault("__EGL_VENDOR_LIBRARY_FILENAMES", "/usr/share/glvnd/egl_vendor.d/50_mesa.json")
```

### Running on NVIDIA (games, CUDA, heavy stuff)

```bash
prime-run <program>
```

## 8. Verification

```bash
# Drivers and modules
lspci -k | grep -A3 -Ei 'vga|display'
dkms status                                   # nvidia and others "installed" for the current kernel
nvidia-smi

# RTD3 (dGPU runtime suspend)
grep 'Runtime D3' /proc/driver/nvidia/gpus/*/power        # Enabled (fine-grained)
cat /sys/bus/pci/devices/0000:64:00.0/power/runtime_status # suspended (when idle)
journalctl -b -u nvidia-rtd3-rebind --no-pager            # workaround result at boot

# Who keeps the dGPU awake (when idle only nvidia-powerd should be there)
sudo lsof /dev/nvidia* /dev/dri/renderD129 2>/dev/null

# Which NVIDIA libraries a process has loaded
grep -oE '/[^ ]*nvidia[^ ]*' /proc/<PID>/maps | sort -u

# DRM card mapping
for c in /sys/class/drm/card?; do echo "$c -> $(basename $(readlink -f $c/device/driver))"; done
```

Note: `nvidia-smi` wakes the dGPU briefly — wait a moment after running it before it is `suspended`.

## 9. After a kernel / driver update

1. Check the pacman output — `dkms` must build `nvidia` for the new kernel without errors.
2. **A reboot is required** when the kernel or NVIDIA driver changes.
3. After the reboot run the checks from section 8 (especially RTD3).
4. Watch [#1507](https://github.com/NVIDIA/open-gpu-kernel-modules/issues/1507) —
   once a new driver reports `Enabled` even without the workaround (`journalctl -b -u nvidia-rtd3-rebind`
   says nothing about a rebind), remove the workaround (section 6).
